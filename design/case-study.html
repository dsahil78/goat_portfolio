The problem

Every new format added another engineering dependency.

Enterprise documents arrive as tables, handwriting, scans, and mixed layouts. A parser tuned for a familiar format could perform well, then fail when a customer introduced a variation.

Six new parsers were planned. That approach tied engineering effort to the growing diversity of customer documents.

What I found

The failures clustered around what we needed to extract.

I audited more than 200 failed extractions. The failures were less about the appearance of the document and more about identifying the information inside it. Separate parsers would repeatedly solve versions of the same underlying problem.

The decision

Define the fields. Let retrieval handle the variations.

KEY DECISION

Shift from format-specific parsers to schema-driven retrieval, so a new document variant could become a configuration change rather than a multi-week build.

What it cost

The general system started behind the hand-tuned one.

The existing parsers performed well on formats engineers had spent time tuning. Moving away from them meant accepting lower initial accuracy on already-solved formats in exchange for a system that could generalize.

That trade-off needed evidence. I built an evaluation framework using annotated benchmarks to assess extraction accuracy, field-level precision, hallucination rate, and confidence calibration. It made the decision testable and guided subsequent releases.

What shipped

A workflow that knows when to ask a person.

The pipeline connected ingestion, classification, extraction, validation, and exception handling. Complexity-based model routing balanced accuracy, latency, and cost. Confidence thresholds determined which outputs could pass automatically and which needed review.

Reviewer corrections fed into system quality. Evaluation informed model selection, prompt iteration, retrieval tuning, and release decisions.

Outcomes

100K+ documents processed each month.

The system reached 95%+ field-level extraction accuracy and reduced turnaround time by 70%. New document variants became configuration changes rather than multi-week engineering projects.

What I learned

A difficult trade-off needs a way to measure progress.

A system that looks strongest on familiar inputs may be expensive to adapt as inputs change. Evaluation gave the team a way to assess the general approach against the hand-tuned one and make release decisions from evidence.
